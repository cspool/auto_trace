# A07：强制串行 Runtime Goal 调度器产出

## Objective

A07 是全部 Skill-producing Goal 之后的强制最终阶段。它消费十个已提交
目标 Skill，生成或幂等校验一个运行时调度脚本和两份只含 Skill 绑定的
pipeline manifest。

本 Goal 只有在后续明确执行迁移 Phase 2 时运行；当前 Phase 1 只生成本
Goal 描述，不修改或重建现有 scheduler、runtime manifests 或 target
Skills。

## 合法输入

- A00、A01、A02、A031、A041、A051、A032、A033、A042、A052 的已提交
  迁移 handoff；
- 上述十个当前项目 Skill；
- manifest 固定的 `runtime_branches` 与 `runtime_outputs`；
- 当前 Codex app-server 的 Goal/Turn 调用方式。

A07 没有规范性源 Skill，也不产出 Skill。

## 强制运行链

```text
Dispatch: R00 -> R01 -> R02 -> R031 -> R041 -> R051
FX:       R00 -> R01 -> R02 -> R032 -> R033 -> R042 -> R052
```

绑定关系必须逐项来自 adaptation manifest：

| Runtime Goal | Skill-producing Goal | Skill |
| --- | --- | --- |
| R00 | A00 | `qwen-dcu-workload-profile-contract-audit` |
| R01 | A01 | `qwen-dcu-profile-patch-targets` |
| R02 | A02 | `qwen-dcu-algorithmic-trace-selection` |
| R031 | A031 | `qwen-dcu-dispatch-trace` |
| R041 | A041 | `qwen-dcu-dispatch-reconstruct-visualize` |
| R051 | A051 | `qwen-dcu-dispatch-visualization-coverage-audit` |
| R032 | A032 | `qwen-dcu-fx-trace` |
| R033 | A033 | `qwen-dcu-fx-process-reconstruction` |
| R042 | A042 | `qwen-dcu-fx-reconstruct-visualize` |
| R052 | A052 | `qwen-dcu-fx-coverage-audit` |

## 必须实现

- `workload_profile/scripts/run_workload_profile.py`；
- `workload_profile/manifests/dispatch_pipeline.json`；
- `workload_profile/manifests/fx_pipeline.json`；
- 通过参数显式选择 `dispatch` 或 `fx`；
- 每个 runtime stage 创建一个持久 thread 上的独立 Goal，即
  `thread/start` 使用 `ephemeral=false`；
- 每个 Goal 只绑定一个 manifest 指定的 Skill；
- Goal prompt 只组合该 Skill、用户运行参数和累计前序 runtime handoff
  ledger；
- 等待当前 Goal 终态，只有 `complete` 才继续；
- `blocked`、`usageLimited`、`budgetLimited`、`paused`、失败、中断、
  handoff 缺失或 ledger 不一致立即停止；
- 使用 `effort=max`，不设置 token budget；
- 提供 `--help` 和完全不创建 Goal 的 `--dry-run`；
- 所有状态与运行产物位于 `${project_root}/workload_profile/`。

manifest binding 只能是：

```json
{"skill": "<target-skill-name>"}
```

不得包含 `goal_spec` 或第二份并行目标合同。

## 幂等边界

若 manifest 声明的三个 runtime output 已存在，A07 必须先静态比较其结构
和绑定。完全符合当前 A07 合同时可以保留文件内容并只完成 Gate；不符合时
才按本 Goal 定义更新。不得以此修改十个 target Skills，也不得执行 runtime
Workflow。

## 轻量完成检查

1. 调度脚本是合法 Python 且 `--help` 可用；
2. Dispatch `--dry-run` 显示六个串行 Goal；
3. FX `--dry-run` 显示七个串行 Goal；
4. 两个 manifest 的顺序与仅 Skill 绑定符合 manifest；
5. 调度脚本不读取 goal-spec，不在 dry-run 创建 Goal 或 runtime artifact。

## 产出

- `workload_profile/scripts/run_workload_profile.py`
- `workload_profile/manifests/dispatch_pipeline.json`
- `workload_profile/manifests/fx_pipeline.json`
- `workload_profile/workflows/project_adaptation/artifacts/A07/handoff.json`

完成静态检查与两条 dry-run 后才可把 A07 标记为 `complete`。
