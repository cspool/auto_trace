# A052：FX 最终 Coverage Audit Gap Skill

## Objective

执行一个强制的 `workflow_gap_skill_generation` Goal，生成：

```text
workload_profile/skills/qwen-dcu-fx-coverage-audit/
```

该 Skill 在 FX reconstruction 与全部手工 visualization 完成后执行最终
provenance、event-set conservation、质量签核和 completion record。

## 唯一权威

能力规范只来自：

- `workload_profile/workflows/03_2_04_2_fx_branch.md`
  - `## 4. Final Coverage Audit`
  - `## Manual Completion Record`
  - 与 final audit 直接对应的 `## Outputs` 和 `## Completion Checks`

当前项目具体绑定只能来自 manifest 固定的 binding evidence：

- `workload_profile/fx/tools/validate_r042_fx_process.py`
- `workload_profile/fx/tools/finalize_r042.py`

这些工具中的旧 `R042` 名称、固定事件/process 数和既有输出只能证明当前
schema 与校验接口，不能成为下一次运行的固定分母或新证据。

## 必须生成

目标文件集合严格为：

```text
SKILL.md
agents/openai.yaml
```

Skill 必须完整编码：

1. 只在 trace、reconstruction 和每事件 visualization 均完成后运行；
2. 重验 source trace、canonical manifest、image、contract、hash、
   event order/count/key-set digest 和 `layer_occurrence` gate；
3. 重验 trace/reconstruction JSON/CSV manifests 的 status、processed count、
   order、uniqueness 和 source-handoff identity；
4. 从当前 handoff 动态构造 `T/X/R/G/V/D`，禁止固定历史事件数；
5. 强制：

   ```text
   T == X == R == G == V == D
   ```

6. 自动 audit 只能证明文件/event coverage；每个 visualization 是否逐
   process 解释并满足手工图质量必须有人审；
7. completion record 必须记录 handoff hash、contract、FX root、动态事件
   数、coverage 结果、人工 review、reviewer 和时间；
8. 任一 missing/error/stale/duplicate/unreviewed 状态都必须阻塞完成；
9. 保持 generated reconstruction 与 manual visualization 分离，且不改写
   历史 reference tree。

## 边界

- A033/R033 拥有 rule reconstruction；
- A042/R042 拥有逐 process 解释和手工图；
- 本 Skill 只审计和形成 completion handoff，不重新生成前述产物；
- 不把 fixed-input FX DAG 当成 full eager、module ownership、custom-op
  internals、并发或分布式覆盖。

## 未决绑定

运行时必须确认：

- 从旧 R042 工具 schema 泛化到 R052 runtime handoff 的路径和字段；
- 当前运行的 visualization review 记录格式；
- 若 FX event directory schema 改变，`D` 集的安全发现规则。

## Handoff

完成后写：

```text
workload_profile/workflows/project_adaptation/artifacts/A052/handoff.json
```

它必须是最小 Workflow-gap handoff，只索引目标 Skill 并声明固定 authority。

## 禁止事项与完成条件

不得执行 FX、模型、GPU 或业务 audit；不得修改 Workflow、binding
evidence、相邻 Skill、manifest、runner、verifier 或 canonical state。

只有两个目标文件完整覆盖 authority、具体绑定均有证据或 runtime
discovery、边界清楚、最小 handoff 写完且外部 gate 可通过时，才可标记
`complete`。
