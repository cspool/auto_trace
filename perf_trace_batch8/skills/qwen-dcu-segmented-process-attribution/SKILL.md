## Template Construction and Matching

direct launch-owned rows:

1. Deduplicate aliases by R02 process/fragment identity and aggregate
   cross-function fragments only by aggregation_key.
2. Sum one-owner R03 kernel instances into process, metric, and source-bucket

## Decimal Arithmetic and Exact Conservation

Parse all numeric text as Decimal. Weight construction, normalization,
allocation, summation, residual placement, and assertions for one group must
remain inside the same explicit localcontext with precision at least 60.
Leaving that context before a 1e-50 assertion is a generator defect, not
evidence of non-conservation.

The required calculation is:

~~~text
D = exact R01 source_layer_metric_ms for one canonical target group
w_i = nonnegative representative raw weight
normalized_w_i = w_i / sum(w_i)
attributed_ms_i = D * normalized_w_i
required_weight_relation = abs(sum(normalized_w_i) - 1) <= 1e-50
required_time_relation = abs(sum(attributed_ms_i) - D) <= 1e-50
~~~

Calculate the final row as the exact Decimal residual D minus the preceding
allocated rows, still within the same context, so serialization does not lose
the group total. Reject a negative residual beyond the tolerance. For a zero
denominator, emit explicit zero_source rows totaling exactly zero while
retaining a valid template and risk label; do not invent positive time.

The generator and independent auditor must each recompute:

~~~text
denominator_group_count
target_layer_occurrence_count
detail_leaf_row_count
template_assignment_count
observed_fx_op_row_count
template_scaled_row_count
nearest_shape_row_count
unmatched_group_count
ambiguous_group_count
maximum_absolute_conservation_error
rank_and_device_coverage
~~~

The auditor must independently parse sealed inputs and outputs and must not
import the generator's allocation, grouping, or conservation functions. Both
implementations use their own explicit high-precision localcontext and must
agree exactly on counts and within 1e-50 on conservation.

## Formal Turn Liveness and Scoped Interruption

Do not use scheduler state.json heartbeat updates alone as proof that the
formal Turn is making substantive progress. Record and monitor all four
signals:

~~~text
last_content_item_time
formal_goal_updatedAt_and_token_time_progress
scoped_active_subprocess_progress
artifact_file_count_size_or_mtime_growth
~~~

Classify a Turn as stalled only when all four signals remain unchanged beyond
one explicit, recorded observation window; use at least 300 seconds unless
the runtime scheduler declares a stricter reviewed value. A live
scheduler/app-server and a two-second state heartbeat do not override four
stagnant signals.

Do not send Ctrl-C to a shared scheduler PTY or foreground process group as a
pause mechanism. When the app-server remains healthy, first read
/proc/<pid>/cmdline and verify that the scoped PID is the scheduler for this
runtime run; signal only that scheduler PID. Wait for scheduler exit or its
confirmed formal pause, then inspect the scoped PID set, Goal state, ledger,
handoffs, and R05 artifact root.

Use continue-current-goal only after the scheduler confirms that the same
formal Goal and Turn were cleanly paused. If pause RPC failed, the app-server
died, or the old Goal remains active without a confirmed pause, do not pretend
the Goal was paused. Once the scheduler has fully exited:

- when the canonical R05 root contains no business file, start a normal
  resume with the constrained resume-artifact-root set to that exact root,
  create a new formal Goal as directed by the outer scheduler, and record the
  abandoned attempt in immutable attempt_history;
- when partial files exist, hash, audit, and either accept them under the same
  proven attempt or isolate them as a failed attempt before any suffix work;
- after a clean scoped pause, the outer scheduler may continue the same
  thread, Goal, and artifact root; and
- on every recovery, revalidate existing files, ledger, all four handoffs,
  target commit/clean state, trace-profile hash, source anchors, helper hashes,
  and output suffix before continuing.

Never overwrite a partial or failed attempt and never mutate R01-R04 during
recovery.

## Attempt Isolation and Offline Revision

Every attempt and revision is immutable and uniquely named. Record input
manifest hashes, helper hashes, failure phase, exception, output files that
exist, and whether any business output was created.

If Decimal generation fails before the output directory is created, preserve
and isolate the old input manifest, write a failure JSON in the current R05
artifact root, record old and new generator and auditor SHA-256 values, and
start a new empty attempt. Keep precision at least 60 and tolerance at 1e-50.
Do not loosen conservation, round through float, change an R01 denominator,

Because R05 is offline, a valid predecessor set is reused byte-for-byte for an
R05 helper defect. Fix only the artifact-local generator, auditor, validator,
or report code and regenerate in a new attempt. A predecessor content or
coverage defect returns to the producer; an R05 defect never authorizes model,
profiler, trace, or PMC execution.

## Validation and Failure Rules

R05 can write a complete scheduler handoff only when all of the following are
true:

- the target commit and clean state, trace-profile hash, exact R01-R04
  handoffs, cumulative ledger, every transitive business hash, and every R05
  helper/output hash validate;
- the inherited workload contains exactly eight successful measured requests,
  concurrency eight, infinite request rate, 1024 output tokens per request,
  two excluded warmups, temperature zero, and ignored EOS;
- DP ranks 0 and 1 and physical DCUs 0 and 1 appear with the declared mapping
  in denominators, templates, assignments, detail, aggregations,
  coverage/risk, reports, manifests, validation, and handoff;
- every R01 denominator group appears exactly once in the assignment and
  coverage tables, and every accepted group has at least one process row;
- all R02 process identities, fragments, aggregation keys, aliases, layer
  types, unresolved states, and expected families remain traceable;
- every direct claim resolves to R03 launch-owned evidence, while every
  normalized estimate is labeled template_scaled and retains its template
  provenance;
- all weight and time conservation checks pass inside explicit Decimal
  contexts with maximum absolute error no greater than 1e-50;
- the independent auditor agrees on denominator groups, target occurrences,
  detail leaf rows, assignments, evidence-class counts, unmatched and
  ambiguous counts, maximum error, and rank/device coverage;
- production output has no unmatched or ambiguous denominator group; optional
  nearest-shape sensitivity rows remain outside production tables;
- R04 values are exact-join diagnostic context only, unavailable attributes
  remain labeled, and no replay clock or order changes timing;
- generated reports reproduce from sealed tables, have the required headings
  and column semantics, and distinguish direct, projected, compatibility, and
  hardware-diagnostic evidence;
- no predecessor or target byte changed, no output was overwritten, and every
  failed attempt or tool revision is accounted for.

Static or offline syntax checks do not count as model or profiler work. Block
on any missing/mismatched predecessor, copied or historical evidence,
profile/request drift, single-device promotion, rank/device pooling before
validation, schema or unit ambiguity, double ownership, missing layer family,
unresolved production assignment, invalid template, negative or non-finite
weight, Decimal context escape, conservation error, generator/auditor count
disagreement, report-shape failure, hardware/timing leakage, overwrite risk,
target drift, or unaccounted interruption.

Preserve failures under attempts/r05_failed_NNN/ or revisions/ as applicable.
Do not write a complete scheduler handoff, do not advance to R06, and do not
weaken a gate to work around a failure.
