## Source-preserving FX Evidence

Produce both shallow and deep evidence for each selected linear-attention and
full-attention case:

- shallow FX evidence preserves the semantic module/function boundaries,
  qualified target paths, source symbols, alias paths, inputs/outputs, and leaf
  decisions;
- deep FX evidence expands traceable operations far enough to reconstruct the
  process/fragment partition while keeping state-mutating custom operators and
  cache updates as explicit, documented leaf boundaries when expansion would
  change behavior;
- every node records its source, operation family, users, shapes/dtypes when
  safely available, process row, and whether it is observed, traced, or an
  audited leaf boundary;
- linear-attention and full-attention traces remain separate and retain their
  real `layer_type`; never substitute one family's graph for the other.

The real Qwen3.5 source writes to output-buffer slices and, in full attention,
expands dynamic `shape[:-1]` into `view(*orig_shape, ...)`. A default
`torch.fx.Proxy` cannot safely express those operations. Use source-preserving
custom Proxy/Tracer behavior that records `setitem` and supplies fixed-rank
`len`/iteration semantics from the hash-pinned sampled shape contract, or
choose an equivalent audited leaf boundary. Preserve assignment ordering and
mutation semantics. A `Proxy object does not support item assignment` or
`Proxy object cannot be iterated` failure must produce a failed-attempt record;
it never authorizes a fabricated, hand-written, or simplified FX graph.

For opaque cache/custom-op boundaries, record the exact source symbol, input
and output shape/dtype contract, mutation/state boundary, and why the leaf is
semantically equivalent. Generated graphs and sidecars must be tied to the
target source-file hashes and AST hashes. Historical FX files may inform the
taxonomy or reconstruction method but are not current source evidence.

## Alias-safe Wrapper Lifecycle

One module object may have multiple qualified layer paths. Discover aliases
without discarding duplicates, then install at most one wrapper for each
`(id(module), wrapper_semantic)` pair. Record every alias path and every
declared layer index separately. Expected event multiplicity is calculated
from declared layer occurrences in the current workload, not from the number
of unique module bindings.

Do not stack one wrapper per alias and then weaken the count gate. In
particular, a shared full-attention rotary object must not emit one nested
adapter event per alias for a single real call. The wrapper registry records
the original callable identity, installed callable identity, semantic role,
aliases, install order, restore order, and cleanup result.

After the measured request completes, wait for active wrapped calls to reach
zero, restore wrappers in reverse order, and prove that every original
callable identity is restored. Unknown replacement, double wrapping,
unbalanced nesting, live wrapper activity, or cleanup failure blocks R02.
