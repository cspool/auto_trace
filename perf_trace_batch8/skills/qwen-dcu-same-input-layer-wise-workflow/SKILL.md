workflow01-10-fresh-e2e. It prepares and captures the fresh, complete

adaptation is not a runtime execution and is not performance evidence.

create_goal. Do not run any part of this skill from an Adapt Goal.

## Preflight Before HIP or Model Initialization

Perform these checks before importing PyTorch, vLLM, or any module that can
initialize HIP:

1. Verify the target path, exact Git commit, clean checkout, profile path and
   profile SHA-256.
2. Validate the request-selection manifest, dataset hash, selected-request
   hash, model config hash, and all scheduler paths.
3. Check KFD/process ownership and exclusivity for both declared physical
   devices. The contract-preparation process must not initialize HIP before
   this check. If either device is busy or identity cannot be established,
   stop and preserve a distinct failed-attempt record.
4. Validate that the environment exposes exactly devices 0 and 1 and that the
   two DP ranks retain the declared native mappings.
5. Direct Python bytecode and compilation caches to the current artifact root
   so the pinned checkout remains unchanged.

When the pinned checkout supplies Python source while the matching installed
vLLM distribution supplies ABI extensions, do not trust the first
importlib.metadata distribution match. Enumerate all distributions named
vLLM, validate the required version against the pinned runtime, and choose the
existing site-packages tree whose file list contains both
vllm/_C.abi3.so and vllm/_rocm_C.abi3.so. Load Python modules from the pinned
checkout. Record source path/hash and both extension paths/hashes in the
contract evidence. Stop on ambiguity, version mismatch, or missing extension.

## Runtime Procedure

These are runtime instructions for a later R01 invocation; adaptation must not
perform them.

1. Validate the serial contract, immutable inputs, target binding, request
   selection, model/runtime provenance, and pre-initialization exclusivity.
2. Materialize or verify only the minimum artifact-local helper surface and
   record helper SHA-256 values.
3. Start the existing DP2 service with both visibility variables set to the
   profile values. The first cold compile is not measured. Restart with the
   same source, model, runtime, caches, and flags, and require logs to show
   cache hits for both ranks, symmetric 28,224-token KV caches, ready
   TunableOp initialization/pre-capture for both ranks,
   speculative_config=None, and compile_sizes=[4096].
4. Execute exactly two request-level warmups, then the fixed eight-request
   concurrent measured workload. Exclude all warmup markers and rows.
5. Acquire the synchronized complete-batch clock evidence and the hipprof
   layer capture with byte-identical request-selection and configuration
   contracts. Preserve every attempt separately.
6. Export native hipprof data and correlate HIPTX ranges, HIP runtime launches,
   and device rows offline. Partition or index outputs by request, DP rank, and
   physical device without discarding the unified capture provenance.
7. Generate the complete input-layer table and concise layer-performance
   report. Do not infer FX/process attribution from layer totals.
8. Run all schema, correlation, conservation, request-count, rank/device
   coverage, and checksum gates. Only then write the R01 handoff.

## Layer Event and Correlation Schema

Preserve the reference layer-event columns as the leading compatibility
schema:

~~~text
event_id,range,layer_idx,phase,q_len,kv_len,workload_type,operator_path
~~~

Append at least:

~~~text
request_id,dp_rank,physical_device_id,pass_id,start_ns,end_ns,duration_ns,runtime_correlation_id
~~~

Every measured layer row must resolve to one of the eight selected requests,
one declared rank, and its declared physical DCU. Keep prefill and decode
separate. Preserve an unambiguous complete-request clock so later R02-R10
stages can retain the same observed time basis.

Strict launch-owned device-row validation applies only to APIs proven by the
native database to launch kernels, including hipLaunchKernel,
hipModuleLaunchKernel, and hipExtModuleLaunchKernel. HIP memory APIs such as
hipMemcpyWithStream, hipMemcpyAsync, and memset operations may appear in the
runtime table without an exported HIPOPS kernel row; do not classify them as
kernel launches through broad memcpy/memset substring rules.

If offline analysis initially fails because the API classifier is wrong,
preserve its failure log and diagnostic counts, fix only the analyzer, and
reuse byte-identical raw database and pftrace inputs. Do not repeat DCU
collection for a pure analyzer defect. Sampled latency attribution remains a
strict evidence gate: CPU clock duration must never be presented as
launch-owned device time.

## Review Policy

Within the already pinned runtime contract, proceed without introducing human
review gates for helper scaffolding, marker plumbing, internally consistent
additive columns, or report wording. Keep the leading compatibility schema and
make every extension explicit. Do not block merely because a table or report
could be prettier. Block when the evidence cannot answer the SAME_INPUT layer
denominator, confuses host and device time, changes the fixed workload, or
fails full DP2 rank/device coverage. Native launch attribution remains strict.

## Validation and Evidence Gates

R01 may be accepted only when all of the following are true:

- the target commit, trace-profile hash, dataset hash, selected-request hash,
  model/runtime provenance, helper hashes, and artifact hashes validate;
- exactly eight measured requests complete successfully with max concurrency
  eight, infinite request rate, 1024 output tokens per request, temperature
  zero, EOS ignored, and exactly two excluded warmups;
- DP ranks 0 and 1 and physical DCUs 0 and 1 all appear in native evidence and
  in per-rank/per-device artifacts;
- the rank-to-device mapping matches the profile and no single-device
  promotion occurred;
- every measured layer event has a valid request, phase, layer, rank, device,
  time interval, and correlation provenance;
- every proven kernel-launch API requiring a device row has one, with no
  memcpy/memset false-positive rule;
- clock totals, layer totals, and profiler totals use declared units and do not
  conflate host time with device time;
- the complete all-input-layer CSV is non-empty, schema-valid, and usable as
  the target-layer denominator for R04;
- the report explicitly documents runtime_correlation_id, HIP launch-owned
  attribution, all input-layer coverage, exclusions, failures, and both-device
  coverage;
- no qwen_dcu.fx_process.* evidence is claimed and no process attribution is
  inferred from R01 layer totals.

Block on missing or mismatched inputs, busy/ambiguous device ownership,
checkout drift, model or ABI ambiguity, incomplete request completion,
warmup contamination, missing rank/device coverage, missing raw data,
correlation failure, schema failure, overwrite risk, or denominator
non-conservation. Preserve failed attempts under unique paths and never accept
their partial artifacts.
