## Strict Runtime and Kernel Ownership

Normalize request, forward, layer, process/fragment, HIP runtime, HIPOPS,
queue, stream, and device rows without losing native IDs or absolute integer
nanosecond timestamps. Ownership is strict and deterministic:

1. For each runtime call, select candidates with the same DB, PID, config,
   rank/device identity, full time containment, and full runtime-index
   containment.
2. Require all remaining parent/fragment candidates to form one strict
   nesting chain.
3. Assign the runtime call and its correlated kernel to the unique deepest
   range.
4. Treat multiple non-nested candidates as ambiguity; do not break ties by
   filename, row order, duration, or broad prefix.
5. Do not double count a runtime/kernel under both a parent and its fragment.
6. Preserve every parent with no directly owned kernel as an explicit
   no-kernel row rather than dropping it or borrowing a descendant kernel.
7. Independently recompute interval containment, nesting, launch correlation,
   ownership, no-kernel state, per-rank/device counts, queue busy union, and
   conservation totals.

## Lossless Gap-aware Live Utilization

The requested sampler period is 500 microseconds, but non-realtime Linux and
vendor RSMI calls cannot guarantee every adjacent interval is below one
millisecond. Do not use a zero-gap assertion or p50/p95 summary as the
completion gate.

The collector must preallocate/in-memory buffer during capture and seal once
after stop. Preserve every real sample with attempt, sequence, rank, native
device, call begin/end, realtime and monotonic timestamps, call latency,
value, alignment uncertainty, and source identity. Preserve every gap interval
and all raw clock anchors. Do not delete, interpolate, resample, smear, impute,
forward-fill, back-fill, or insert zero samples.

Rows whose alignment uncertainty exceeds one millisecond remain present and
receive `unavailable_alignment_error`. A process interval receives a numeric
live-utilization value only when at least three timing-eligible real samples
fall inside the exact interval and the interval does not intersect an
unobserved gap. Otherwise preserve the process row and assign exactly one
applicable state:

~~~text
unavailable_intrinsic_short_window
unavailable_sampling_gap
unavailable_alignment_error
~~~

Fully recorded isolated gaps do not by themselves fail request/process/
runtime/kernel target coverage. They do reduce live-utilization availability
for intersecting processes. Target coverage and utilization availability are
separate denominators. Any hidden gap, dropped raw row, fabricated continuity,
or low-utilization conclusion for an unavailable process is fail-closed.

The workflow's observed diagnostics included 24/38 adjacent gaps at or above
one millisecond in two captures, a maximum stopped-state scheduling gap of
19.4 ms, periodic roughly 2.5 ms driver calls, and four over-limit uncertainty
rows. Treat these only as regression evidence that gap-aware semantics are
required; never copy their values into the current capture or claim current
availability from them.

The canonical alignment outputs retain absolute begin/end nanoseconds as
decimal strings or integer-safe values, native rank/device identity, sample
counts, gap intersections, uncertainty, availability reason, and source raw
hashes. R09/R10 may consume live-utilization values only where R07 marks the
process `available`; gaps and unavailable intervals remain a separate evidence
track.

## Failure, Stop, and Resume Rules

The first measured-workload failure in a formal R07 Goal ends that attempt.
Do not silently retry within the Goal, reuse its nonempty root, concatenate
timing/utilization/events, or promote a successful subset. Seal raw bytes,
sidecars, samples, gaps, anchors, tool hashes, lifecycle counts, and a blocked
audit first.

Before retry, prove the serial run is `stopped` and every scoped service,
model, profiler, collector, and scheduler-child process has exited. Only the
serial scheduler may resume the same run from R07 and create a new formal Goal
with exactly one new non-replay measured-workload authorization and a new
empty R07 attempt root inside the canonical stage boundary. Revalidate R01-R06,
the target, device isolation, authorization, and every CPU/device gate.

The scheduler entry is ordinary
`--resume-run-id <same-run-id> --resume-from R07`, which allocates a new empty
`R07/resume-NNN` root. The already generated A11 scheduler bundle is an
immutable entry point; a runtime retry never reruns A11 or any other Adapt
Goal.

Never use `--continue-current-goal` for a blocked formal Goal. Never rerun
Adapt A01-A11 or runtime R01-R06 to repair R07, and never start R08 after a
failed R07. A clean pause before failure may follow scheduler-owned
continuation semantics, but it must preserve attempt identity and cannot add
measurement authorization.

A failure before device query/model import records zero lifecycle counts and
may be corrected only in a new immutable tool attempt. A failure after the
formal preflight preserves that preflight. A failure after model or measured
work always requires the full new-Goal/new-empty-attempt procedure. No failure
can be fixed by weakening coverage, hiding gaps, changing filenames in place,
or rewriting raw evidence.
