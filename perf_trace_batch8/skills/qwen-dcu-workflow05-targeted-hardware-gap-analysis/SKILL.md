Seal raw output, logs, lifecycle counts, token/literal bindings, and hashes
before normalization or any postcheck. Non-target rows from a bounded
superset remain immutable raw evidence with an explicit exclusion reason.
Never delete them, rewrite raw names, or count replay wall time as latency.

## Exact Attribution and Observed-clock Attachment

Accept a normalized PMC attribute only when all links are proven within the
same physical replay and against the sealed same-lineage inputs:

~~~text
R06 logical hardware-family target
  -> byte-exact R06/R02 kernel_name_filter_literal
  -> recorded HIPProf collector_kernel_name_token
  -> exact R02 HIPTX process or fragment range in this replay
  -> proven HIP runtime launch owned by that exact range
  -> native HIPOPS/PMC dispatch correlation in this replay
  -> exact full literal, PID, dispatch order, rank, and physical device
  -> exact normalized R03/R07 kernel-family subsequence and stable target ID
  -> immutable R07 observed process/kernel interval used only as join context
~~~

Kernel token, name substring, replay time overlap, pass order, row proximity,
shared raw membership, or repeated literals are insufficient. Shared-token and
shared-literal captures may serve multiple logical targets only after each
target independently proves range, launch, correlation, subsequence,
multiplicity, and rank/device identity. Preserve unmatched, ambiguous,
duplicate, non-target, and no-kernel rows with reason codes; none enters the
projected attribute table.

The normalizer and an independent auditor separately derive eligible targets,
expected multiplicity, mapped dispatch count, rejection counts, counter
availability, and per-rank/device coverage. They must agree without importing
one another's selection or mapping implementation.

Every normalized row carries at least the stable family/target/process/
fragment/kernel IDs, full literal and token hashes, request contract, DP rank,
native device, counter name/value/unit/formula, raw dispatch provenance,
catalog/tool/plan hashes, evidence class, mapping state, and the R07 join key.
Do not mix incompatible counter passes as simultaneous observations or
fabricate a missing metric.

## FX-visible Traffic and Resource Model

Build the model from hash-validated same-run identities and evidence:

- R02 FX-visible nodes, process/fragment boundaries, tensor shape/dtype and
  marker identities;
- R03 launch-owned kernel-family order and non-replay timing context;
- R05 full-layer process taxonomy, attribution, and no-kernel/unresolved state;
- R06 hardware-family inventory, target grouping, and selection state;
- R07 observed request/process/kernel intervals, strict ownership, live-
  utilization availability, dependency identities, rank, and native device;
  and
- attributable R08 PMC counters and current device capability formulas.

For each logical process/fragment/kernel family and each applicable rank/device,
record the exact source rows and derive only defensible quantities such as
FX-visible input/output/parameter/intermediate bytes, element counts, dtype
widths, declared FLOP formula, measured native DRAM/L2 traffic, compute-unit
activity, occupancy, wave/register/LDS pressure, and stall families when the
current catalog supports them. Every field records value, unit, formula,
assumptions, source hashes, aggregation rule, evidence class, and availability.

Static shape-derived traffic is `derived_static`; counter-based traffic or
resource state is `replay_projected`; R07 time and utilization remain
`observed_r07`; joins or ratios combining them are
`derived_from_observed_and_replay_projected`. Never call a theoretical byte
count measured traffic, infer unavailable counters from duration, replace an
unknown with zero, or use a replay timestamp as an observed begin/end.

Avoid double counting nested parent/fragment ranges and shared physical
captures. Attribute a runtime/kernel to the exact deepest valid owner inherited
from R07, roll fragments to a parent only through the declared aggregation key,
and retain both base rows and aggregation provenance. No-kernel processes and
capability-proven unavailable metrics remain explicit model rows.

`model/traffic_resource_model.json` must provide deterministic schemas,
formula/version hashes, lineage and profile identity, source manifests,
logical-family coverage, request/rank/device coverage, capability states, raw
and normalized counter references, R07 observed-clock references, and the
observed/replay/derived vocabulary. The CSV attachment is a lossless tabular
projection, not an independent source. An independent auditor recomputes row
membership, joins, units, formulas, aggregation conservation, availability,
and evidence labels from sealed inputs.

## Immutable Attempts, Failure, and Resume

The following rules are distinct and must not be collapsed:

- The canonical root-binding failure paired the real R02 inventory with an R08
  root, stopped after model load but before warmup/request/replay, and had
  `completed_capture_count=0`. Its empty DB/PMC files, logs, and progress are
  diagnostic-only. Preserve the canonical root and `attempt-001`. After the
  run is stopped and scoped processes are zero, ordinary scheduler resume with
  `--resume-run-id <same-run-id> --resume-from R08` creates a new formal Goal
  and a new empty `R08/resume-NNN` root. It must not continue the blocked Goal,
  reuse the attempt, or rerun Adapt Goals or R01-R07.
- A launcher permission or missing-parent error before any device action is a
  prelaunch tool failure. Preserve its logs, frozen hashes, and zero lifecycle
  counts in an immutable diagnostic/quarantine revision. Because no device
  capture occurred, resume the same logical capture ordinal and attempt name,
  but place the corrected invocation in a new empty immutable
  `prelaunch-revision-NNN` driver subroot. Do not overwrite the diagnostic,
  rename it into evidence, increment accepted-capture count, or rerun an
  accepted prefix.
- After one or more nonempty captures have been accepted, a zero-byte required
  PMC output is fail-closed and contributes no normalized counter. Prove the
  run is `stopped` and all scoped model/device/profiler processes exited, then
  record a retry authorization. The scheduler resumes from R08 with
  `--resume-artifact-root <original-R08-root>`, hash/semantically validates and
  skips every accepted prefix capture, preserves sealed plan/lineage, bytes,
  wall-time and failure cost, and allocates a new empty `attempt-NNN` only for
  the first failed literal/mode and its unstarted suffix.
- The full-literal, escaped-literal, and regular-expression HIPProf attempts
  with nonempty DB but empty PMC text remain diagnostic-only. Correct token
  transport uses the same suffix-only recovery rule and cannot change their
  bytes or claim their durations/counters.
- A valid raw capture is not repeated for a CPU normalizer/auditor defect.
  Archive the capture-time tool manifest, failed analysis, partial outputs,
  stderr, and tool hashes; repair only in a new
  `normalized-repair-NNN/` root. A large CPU-only normalizer runs as a
  persistent pollable process so an interactive timeout cannot silently
  truncate and promote a CSV.

Never use `--continue-current-goal` for a blocked formal Goal. Never rerun
A01-A11, R01-R07, an accepted R08 prefix, or the full R08 stage merely because
suffix recovery is difficult. If the recovery code cannot prove prefix
integrity or cannot append through a new attempt, remain stopped. Never weaken
nonempty-output, exact-attribution, full-DP2, or evidence-boundary gates.

## Evidence State and Advance Semantics

Keep these fields independent:

- `status=complete` means the bounded R08 stage reached a valid terminal
  handoff state.
- `execution_status=complete` means its authorized procedure ended; it does
  not alone prove attribute sufficiency or coverage.
- `evidence_status` is `complete`, `degraded`, `insufficient`, or `unknown`.
- `coverage_target_met` covers every R06 selected logical family, all eight
  requests per accepted replay, both ranks/devices, attribution, and the model
  inventory.
- `next_authorization_required` controls whether R09 may start.

A capability-proven unavailable optional counter can be complete evidence of
unavailability when its logical family remains accounted for. A missing probe,
unknown required capability, unattributed capture, hidden target, or partial
rank/device/request coverage is not complete evidence.

The only R09-advance-eligible state is:

~~~text
status=complete
execution_status=complete
evidence_status=complete
coverage_target_met=true
next_authorization_required=false
fresh_e2e_evidence.schema_version=1
fresh_e2e_evidence.status=complete
fresh_e2e_evidence.lineage_id=<same nonempty lineage used by R06-R10>
~~~

A valid terminal handoff may describe degraded, insufficient, or unknown
evidence with a false or null coverage state and
`next_authorization_required=true`; it is not an advance token. A failed replay
that has not reached a valid terminal stage writes no complete handoff. The
scheduler must never infer evidence sufficiency from `status=complete` alone.

## Deterministic Runtime Procedure

Execute R08 in this order, with sealed checkpoints between phases:

1. Resolve the scheduler-assigned artifact and handoff paths, run/attempt IDs,
   retry authorization, and monitor advisory; prove output separation and the
   applicable empty/new or suffix-resume boundary.
2. Validate the hash-pinned profile, immutable target, exact R01-R07 prefix,
   same lineage/request/topology, all transitive hashes, R06 bounded plan, and
   R07 observed-clock contract.
3. Create artifact-local helpers, construct production argv/environment/path
   bindings, freeze all bytes, and complete the standalone CPU-only predevice
   gate. End the tool call and publish its checkpoint.
4. In a later tool call, perform formal device occupancy, source/ABI, HIPProf,
   gfx936 counter, and native-device capability preflight; seal raw responses
   and publish its checkpoint.
5. Resolve exact native counters and deterministic physical batches into an
   immutable R08 plan revision; independently audit family coverage, token
   mapping, budgets, compatibility, and DP2 applicability before replay.
6. Execute authorized PMC capture attempts serially. For each attempt preserve
   the full DP2 batch8 request contract, seal raw bytes and lifecycle/device
   release state, validate the manifest, then checkpoint before the next pass.
7. Normalize only accepted raw captures, apply the exact attribution chain,
   retain unmatched/superset states, and independently audit mapping and
   rank/device conservation.
8. Build and independently audit `device_capabilities`,
   `targeted_pmc_manifest`, and the FX-visible `traffic_resource_model` while
   keeping R07 observed time separate from R08 replay attributes.
9. Re-hash every source, predecessor, tool, plan, raw manifest, normalized
   table, model, and audit; verify target/source immutability and business/
   handoff separation; write the R08 source-lineage and artifact manifests.
10. Derive execution/evidence/coverage/authorization fields from the sealed
    audits. Write exactly one runtime handoff only when the applicable terminal
    gate permits it.

Do not combine CPU preparation, device preflight, model initialization,
replay, normalization, and reporting into one command. R08 has no reporting
phase; R09/R10 remain scheduler-gated successors.

## Formal Turn Liveness and Scoped Interruption

Do not classify progress from an app-server heartbeat alone. During a large
artifact-local builder, normalizer, or auditor generation, inspect the last
content item, formal Goal token/time changes, scoped subprocess progress, and
artifact size/hash growth at five-minute intervals.

The workflow records that a roughly 45-85 KiB builder/auditor can leave all
visible signals unchanged for more than one interval and then recover. For a
Turn explicitly in that phase, require two consecutive complete five-minute
observations with every signal stagnant and no new reasoning item before an
interrupt is considered.

Any interrupt targets only the cmdline-verified scheduler PID after sealing
its PID, argv, run ID, and stage. Never signal a shared PTY, process group, or
app-server. Confirm stopped state and scoped model/device/profiler process exit
before applying the R08 recovery rules. A blocked formal Goal is never
continued in place.
