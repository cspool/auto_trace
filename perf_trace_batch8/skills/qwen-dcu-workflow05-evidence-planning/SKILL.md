## Evidence, Coverage, and Advance State

Keep these concepts independent:

- `status=complete` means the bounded CPU-only R06 stage finished its declared
  work and wrote a valid scheduler handoff.
- `execution_status=complete` means the offline admission, enumeration,
  planning, probing, and audits finished; it says no model run occurred.
- `evidence_status` describes whether target, capability, and planning
  evidence is complete, degraded, insufficient, or unknown.
- `coverage_target_met` describes the complete request/target/rank/device and
  required hardware-family planning gates.
- `next_authorization_required` controls whether R07 may start.

An advancement-eligible R06 handoff must contain exactly:


It cannot be relabeled as the advancement-eligible form without new,
hash-validated R06 evidence and a new immutable attempt/revision.

Capacity failure, incomplete target enumeration, prefix drift, target drift,
or a missing independent audit is fail-closed and writes no complete handoff.
The scheduler must never infer evidence sufficiency from `status=complete`
alone.

## Deterministic Runtime Procedure

Perform R06 in this order, with a checkpoint after each sealed step:

1. Resolve `runtime_artifact_root` and `runtime_handoff_output`; prove they
   are distinct and the artifact root belongs to this run/stage.
2. Validate the trace profile, immutable target binding, exact R01-R05
   cumulative prefix, direct/transitive hashes, producer semantics, request
   contract, and complete DP2 coverage.
3. Freeze and hash the artifact-local helpers without importing the target
   runtime or any accelerator-initializing library.
4. Write and independently audit the fresh-run lineage manifest.
5. Enumerate all parent and fragment targets, canonicalize and deduplicate,
   record exact counts, and run the independent count/name/coverage audit.
6. Apply the capacity gate only after complete enumeration. Stop with the
   immutable failure diagnostic when insufficient.
7. Write the full request target tables and their manifest only after the
   capacity and transport audits pass.
8. Build the complete hardware-family inventory and bounded R08 plan; run the
   independent membership, budget, evidence-class, and DP2 applicability
   audit.
9. Run isolated, no-network offline capability probes and validate any
   claimed fallback.
10. Re-hash all inputs, helpers, and outputs; verify target/source
    immutability; write the artifact manifest and completion audit.
11. Derive execution/evidence/coverage/authorization state from recorded
    checks. Write one runtime handoff only when the applicable handoff gate
    permits it.

Do not combine a failed attempt with a later successful attempt. New helper
bytes, parameters, or probe logic require a new immutable attempt or revision
with old/new hashes and a reason.

## Formal Turn Liveness and Scoped Interruption

Do not treat an app-server heartbeat alone as progress. During a long R06
builder or auditor generation, record at least the last content item, formal
Goal token/time updates, scoped subprocess progress, and artifact size/hash
growth. Ordinary checks occur every five minutes.

The workflow records that generating roughly 45-85 KiB CPU-only builder or
auditor files can legitimately leave all observable signals unchanged for
more than one interval and then resume. When the Turn is explicitly in such a
generation phase, require two consecutive complete five-minute observations
with all signals stagnant and no new reasoning item before considering an
interrupt.

Any interrupt targets only the cmdline-verified scheduler PID after proving
its PID, argv, run ID, and stage. Never signal a shared PTY or process group,
and never target app-server. Confirm the resulting run state and scoped
process exit before recovery. A blocked formal Goal is not continued in
place; use the scheduler's serial resume rules and preserve every attempt.

## Validation and Failure Rules

R06 can authorize R07 only when all of the following pass:

- the hash-pinned workflow/profile identity, target commit/clean state,
  exact R01-R05 handoffs, current cumulative ledger, and every transitive
  business hash validate;
- the same runtime branch, run ID, lineage, selected request, model contract,
  and trace-profile hash are preserved with no external runtime evidence;
- workload semantics remain eight ordered measured requests at concurrency
  eight, infinite request rate, 1024 output tokens, two excluded warmups,
  deterministic decoding, and ignored EOS;
- request/rank/device coverage includes every measured request, ranks 0 and
  1, physical DCUs 0 and 1, and the exact rank mapping;
- every R02 parent and fragment is enumerated before the capacity check,
  deduplication is schema-exact, unresolved/no-kernel states are retained,
  and the independent target count and marker transport audits agree;
- `maximum_selected_process_count` is no less than the exact unique universe,
  and any prior capacity revision has a stable ID plus complete immutable
  diagnostic/state/ledger provenance;
- full target CSV/JSON rows, manifest counts, per-rank/per-device counts, and
  ordered canonical hashes agree with the independently reconstructed values;
- the full hardware-family inventory is sealed, the bounded plan obeys its
  explicit budget and deterministic policy, every exclusion is visible, and
  no replay property is presented as observed timing;
- offline capability states are supported by sealed local probes, preferred
  interface absence is distinguished from fallback failure, and no network,
  model stack, or accelerator access occurred;
- all helpers and outputs re-hash, the target and predecessor trees remain
  unchanged, the artifact manifest excludes the scheduler handoff, and the
  independent completion audit agrees with the claimed state.

Fail closed on any missing or mismatched predecessor, copied/historical
evidence, cross-run or cross-branch input, external ledger, profile/request
drift, target dirtiness, device/rank pooling, early capacity check, target
truncation, dropped fragment, invented marker, broad-prefix selection,
duplicate ownership, hidden unresolved/no-kernel row, historical-count
substitution, unhandled optional-module exception, networked capability
probe, unvalidated fallback, hardware-family budget overflow, silent family
exclusion, replay/observed evidence leakage, helper drift, output overwrite,
or independent-audit disagreement.

Preserve each failure under a new `attempts/r06_failed_NNN/` or immutable
revision/recovery directory. Never weaken a gate, overwrite an earlier
attempt, edit a predecessor, fabricate a handoff, or start R07 to work around
a failure.

## Runtime Handoff

After every business artifact and applicable validation passes, write one
JSON handoff only to `runtime_handoff_output`. An advance-eligible handoff
contains at least:

~~~text
status=complete
execution_status=complete
evidence_status=complete
coverage_target_met=true
next_authorization_required=false
runtime_branch=workflow01-10-fresh-e2e
runtime_goal=R06
runtime_predecessors=R01,R02,R03,R04,R05
model_execution_performed=false
gpu_dcu_execution_performed=false
profiler_execution_performed=false
trace_collection_performed=false
pmc_collection_performed=false
report_generation_performed=false
capability_probing_performed=true
target_planning_performed=true
hardware_family_planning_performed=true
~~~

Also record the runtime run, attempt, and lineage IDs; exact cumulative-ledger
path/hash; R01-R05 handoff paths/hashes; predecessor artifact-manifest and
consumed business hashes; target commit, clean state, and source-anchor
hashes; trace-profile path/hash; complete workload and topology; selected
request hashes; rank/device mapping and coverage; parent, fragment, unique,
alias, unresolved, and no-kernel counts; configured capacity and revision
history; fresh-lineage manifest; full target tables and manifest; marker
transport audit; complete hardware-family inventory; bounded R08 plan and
coverage; capability records and fallback states; independent audit;
artifact manifest; attempt/revision inventory; all explicit false execution
fields; nested `fresh_e2e_evidence`; and the exact R07 advance gate.

The scheduler may advance only after it independently validates the handoff,
all referenced paths/hashes and counts, `evidence_status=complete`,
`coverage_target_met=true`, `next_authorization_required=false`, the full
batch8 DP2 mapping, and the nonempty same-run lineage. Keep the handoff
outside the business artifact manifest. This Adapt-created skill does not prove that R06
or any performance workflow ran; neither does the A06 Adapt handoff.
