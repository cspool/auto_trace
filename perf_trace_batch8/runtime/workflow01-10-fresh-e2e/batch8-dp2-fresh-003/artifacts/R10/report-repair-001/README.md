# R10 排名时间线：折叠梯形分组

本目录仅修订已封存 R10 的展示，同一份 Batch8 DP2 trace 与硬件证据，没有重新执行模型、采集或改写前序数据。完整页面与历史候选放在 Release；代码、排名、日志、检查和发布回执提交到本仓库。

## 查看

下载发布包 `R10_ranked_folded_timelines.zip`，完整解压后用桌面浏览器打开 `index.html`。各分析 HTML 自带数据，可直接离线打开；跨页面导航及原始无损视图需要整个 ZIP。

- 高延迟：50 个可比较组 / 1,237 个高延迟实例，默认前 20 组；按组内 R07 观测时长总和排名，父过程和 fragment 不可跨组加总。
- 双卡并发：16 个请求/阶段组，全部显示；按本请求/阶段的 selected-kernel 并集排名，两张卡各自保留 kernel/queue 分段。
- 原始利用率：13 个可用过程类型组，全部显示；按组内最长可用过程窗口排名，原始点不插值、不补零。
- 未知采样缺口与相邻 kernel 间隔：各自默认前 20 项，全部排名仍可搜索、定位和逐页查看。

## 完整过程时间线的尾部裁剪

默认精确时间线已移除没有细粒度追踪的 Request 尾部：整图原客户端包络 744.747 s，保留 192.958 s，省略末尾 551.789 s。每个 Request 按其最后一条 Process/kernel/HIP Runtime/layer/forward 记录结束裁剪；原始客户端结束时间不变。图前列出已追踪与未展示范围、整图及逐请求省略时长。详见 `REQUEST_VIEW_SCOPE.json` 与 `validation/REQUEST_TRIM_AUDIT.json`。

所有 Process、kernel、Runtime、layer/forward 的原始区间均保留；仅 Request 的显示端点及默认视窗改变。`original/` 是封存原始数据归档，默认入口指向修订后的页面。

## 梯形与折叠的含义

分组内每个 Process 对应一条横线，左右两端保留其真实开始/结束。为让短过程在全组视图中可见，默认使用分别标注的起止双轴；两轴不是一根连续横轴，连接线长度不代表耗时。点击横线会定位实例；下方单实例图保留连续真实时间轴和 kernel / 硬件或原始采样证据。

长间隔用 `//` 标记折叠；所有相邻源端点区间保留，显示权重上限为组内过程时长中位数的两倍。展开折叠明细可查每段真实起止、实际间隔、显示权重和压缩倍数。切换为单轴并取消折叠，即恢复按真实时间比例显示。全组概览压缩纵向间距，展开逐行后每条横线占 36 px；所有实例均可点击，不截断尾部。

## 证据边界与校验

八请求全部保留首个 prefill/decode 的过程 trace，不能解读为 1024 个解码步都有过程追踪。R08 重放只作硬件属性旁证，不参与延迟排名。采样缺口不是零利用率，selected-kernel 间隔不是设备空闲；跨设备同轴显示不证明细粒度时钟同步。

`validation/REVISION_AUDIT.json` 独立对照 R09 CSV；`validation/BROWSER_AUDIT.json` 记录禁止网络后的交互与截图检查；`BUILD_MANIFEST.json` 证明所有原始内嵌数据字节不变。`original/` 是原始 R10 完整副本，`attempts/` 保留本次展示候选、工具、日志和审计历史。
