# P05：补全 Workflow 03 的 DCU process 硬件画像 Skill

## Objective

本 Goal 补全参考 Skill 没有覆盖、但 Workflow 03 明确要求的 process GPU
硬件属性能力，产出新的独立 Skill：

```text
qwen-dcu-process-gpu-hardware-trace
```

它不是 `visipruner-process-performance-breakdown` 的文本迁移，也不得把硬件
采集方法塞进 P03。P02/P03 继续拥有 process marker、launch ownership、
非 replay timing 和 process/kernel-family 顺序；P05 只拥有在这些已确定行上
采集、连接和解释 DCU replay 硬件属性的能力。

## 权威来源

能力规范的唯一来源是：

- `perf_trace/workflows/03_process_gpu_hardware_trace.md` 的完整硬件属性范围。

当前项目具体绑定的唯一证据是：

- `pra2026-bh408/scripts/perf_trace/analyze_qwen_hipprof_process_trace.py`；
- `pra2026-bh408/scripts/perf_trace/prepare_qwen_dcu_hardware_plan.py`；
- `pra2026-bh408/scripts/perf_trace/run_qwen_hardware_profile_single_request.sh`；
- `pra2026-bh408/scripts/perf_trace/analyze_qwen_hipprof_pmc.py`；
- `pra2026-bh408/scripts/perf_trace/consolidate_qwen_dcu_hardware_metrics.py`。

上述当前项目文件只证明 Qwen3.5/gfx936 DCU/hipprof 的工具、schema 和证据
边界，不能作为本次运行的新测量证据。Workflow 中的 NCU/CUDA 命令已经被
当前项目的 hipprof/ROCm/DCU 实现替代，不得原样复制，也不得发明未在这些
文件中出现的 DCU counter、命令或 schema。前一轮迁移使用的
`perf_trace_bk` 路径已退役，只保留在 predecessor state 中作为历史 provenance，
不得成为新 Goal 的当前绑定。

## 必须生成的 Skill

目标目录：

```text
perf_trace/skills/qwen-dcu-process-gpu-hardware-trace/
```

文件集合必须严格为：

```text
SKILL.md
agents/openai.yaml
```

Skill 必须完整编码：

1. 只消费 Workflow 02/P02/P03 已确定的 representative process 顺序、
   HIPTX 范围、launch-owned kernel 与 `matched_kernel_family` 行；
2. 覆盖所有 Workflow 02 representative parent layers；过滤只允许用于显式
   debug/batch，不能宣称完成；
3. 使用独立 replay 采集，按当前项目证据解析 hipprof `pmc`、`pmc-read`、
   `pmc-write`，不得把 replay 与非 replay timing 合并；
4. 不新增 Workflow-03-only process markers，复用 Workflow 02 的边界；
5. 将 replay kernel 严格连接回 Workflow 02 的非 replay
   `event_id + stage + matched_kernel_family` 行；
6. 主报告以 matched kernel family 为行，不以 process summary 或单个 replay
   kernel instance 为行；
7. 输出 selection plan、replay metrics、family-level hardware projection、
   coverage JSON 和 DCU hardware report；
8. 记录 activity、matrix-core proxy、L2 read/write/hit、occupancy 上界和 stall
   proxy；不可用指标必须显式标记，不得伪造 NVIDIA Tensor Core/DRAM 等价值；
9. replay kernel 时间永远不是 latency 证据，不得改变 Workflow 02 timing 或
   Workflow 04 denominator；
10. 校验全部代表范围覆盖、kernel/name/order join、missing/partial 状态、
    replay instance-count drift 和非 replay timing 边界；
11. 若 replay 改变 kernel family 或执行路径，应停止 latency 解释并要求重新
    生成 Workflow 02 证据。

不得把归档运行中的固定 `9` 个 event、`87` 个 process 或具体统计数写成通用
完成条件；运行时应从当次 Workflow 02 handoff 推导期望分母。
