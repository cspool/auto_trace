# P06：perf_trace 完整串行运行时 Goal 调度器

## Objective

本 Goal 不再生成 Skill。它消费 P01–P05 已提交的五个当前项目 Skill，生成
一个运行时调度脚本及其 Skill-only manifest：

```text
R01 layer-wise
 -> R02 process instrumentation
 -> R03 process performance breakdown
 -> R04 process GPU hardware trace
 -> R05 segmented process attribution
```

Workflow 03 已由 P05 的 `qwen-dcu-process-gpu-hardware-trace` 覆盖，必须进入
运行链；不得再标记为 ignored、unsupported 或 unscheduled。

## 合法输入

- P01、P02、P03、P04、P05 的已提交 handoff；
- 五个已适配或补全的目标 Skill；
- `perf_trace/workflows/01_layer_wise_end_to_end_trace.md`；
- `perf_trace/workflows/02_representative_fx_process_wise_trace.md`；
- `perf_trace/workflows/03_process_gpu_hardware_trace.md`；
- `perf_trace/workflows/04_full_layer_fx_process_wise_estimate.md`；
- 当前 Codex app-server 的 Goal/Turn 调用方式。

## 必须实现

- `perf_trace/scripts/run_perf_trace.py`；
- `perf_trace/manifests/core_attribution_pipeline.json`；
- 通过 `--branch core-attribution` 显式选择唯一支持的分支；
- 按 `R01 -> R02 -> R03 -> R04 -> R05` 串行创建五个独立 Goal；
- 每个 Goal 只绑定对应的一个目标 Skill；
- 创建运行 Goal 时，将该 Skill、用户运行参数和截至当前的累计前序 runtime
  handoff ledger 组成 prompt；R01 没有前序 handoff；
- 每个 Goal 创建在持久 thread 上，即 `thread/start` 使用
  `ephemeral=false`；
- 等待当前 Goal 到达终态；只有 `complete` 才启动下一个 Goal；
- `blocked`、`usageLimited`、`budgetLimited`、`paused`、失败或中断立即停止；
- Goal 使用 `effort=max`，不设置 token budget；
- 提供 `--help` 和完全不创建 Goal 的 `--dry-run`；
- 所有状态和运行产物位于 `${project_root}/perf_trace/`；
- 不生成或消费 goal-spec；
- R04 replay 诊断不得替换 R03 的非 replay timing，也不得改变 R05 使用的
  layer timing denominator。

manifest 必须为：

```json
{
  "schema_version": 1,
  "branch": "core-attribution",
  "goals": ["R01", "R02", "R03", "R04", "R05"],
  "bindings": {
    "R01": {"skill": "qwen-dcu-same-input-layer-wise-workflow"},
    "R02": {"skill": "qwen-dcu-fx-process-nvtx-instrumentation"},
    "R03": {"skill": "qwen-dcu-process-performance-breakdown"},
    "R04": {"skill": "qwen-dcu-process-gpu-hardware-trace"},
    "R05": {"skill": "qwen-dcu-segmented-process-attribution"}
  }
}
```

binding 不得含 `goal_spec` 或其他并行文本合同。不要求跨分支 DAG、业务
Gate、fake app-server 测试、GPU/模型测试、provenance matrix 或 acceptance
matrix。

## 轻量完成检查

1. 调度脚本是合法 Python 且 `--help` 可用；
2. `--branch core-attribution --dry-run` 显示五个串行 Goal；
3. manifest 的顺序和仅 Skill 绑定完全符合上文；
4. 调度器使用持久 thread，且不包含 goal-spec。

## 完成条件

完成两个运行时文件、最小 handoff 和上述轻量静态检查后即可把 P06 标记为
`complete`。不得在本 Goal 中启动生成出来的非 dry-run 调度流程。
